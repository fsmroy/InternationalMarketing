Problem 1AHP 二階層評估

📄 作業原文（English Original）

Using AHP to conduct a two-level assessment for three harbors in the world, Kaohsiung, Busan, and Tokyo. The criteria includes living cost, natural environment, city tourism, food, transportation, and courtesy. Please draw a plot to visualize the process of assessment. Then, calculate the average weights of the four criteria based on your team members. Third, conduct assessment for three cities with respect to all criteria. Finally, calculate the weighted score for three cities.

📋 題目說明（小學生版）

想像你在選「畢業旅行去哪裡」。
有三個候選城市：高雄、釜山、東京。要選哪一個，不能只憑「我喜歡」，要把理由拆開來看， 例如：生活費便宜嗎？風景美嗎？好玩嗎？東西好吃嗎？交通方便嗎？人親切嗎？——這六個理由就叫「準則」。

AHP 在做什麼？就是「把模糊的喜好，變成一串數字分數」。做法是一次只比兩個：

  • 比準則：「生活費」跟「風景」哪個比較重要？重要多少？（用 1～9 分打分，1 = 一樣重要、9 = 超級重要）。
  • 比城市：在「風景」這一項，高雄跟東京誰比較美？

每一組兩兩比較累積起來，用數學算出每個準則的權重（重要度），再算出每個城市的加權總分，就排名了。

名詞小學生翻譯
二階層（two-level）兩層樓：樓上是「準則」，樓下是「城市」。
成對比較一次只比兩個，像「我和你的身高誰高」，不全部一起比。
權重 w這個理由有多重要（加起來 = 1）。
一致性 CR檢查你的答案有沒有「自相矛盾」（例如說 A 比 B 好、B 比 C 好，卻又說 C 比 A 好）。CR < 0.1 才算邏輯通順。

公式

逐欄正規化：a[i][j] = a[i][j] / (該欄總和)　→　權重 w[i] = 每列平均
一致性：λmax（最大特徵值）、CI = (λmax − n) / (n − 1)、CR = CI / RI
RI 表：n=3→0.58、4→0.90、5→1.12、6→1.24、7→1.32、8→1.41、9→1.45、10→1.49
城市加權總分：Score = Σ（城市在某準則的得分 × 該準則權重）

🖱️ 操作步驟

1確認作業資料夾有 ahp_weights.csv（各成員六準則權重，每列加總 = 1）與 city_scores.csv（各城市六準則 1~5 評分）。
2要換資料時：直接改這兩個 CSV（用 Excel 開可編輯，記得存檔）。
3執行 P1_AHP.R。Console 會依序印出：準則權重、CR、城市×準則平均評分、城市×準則相對得分、加權總分與排名。
4作業資料夾會出現 P1_AHP_hierarchy.png（含階層圖與分數）與 P1_ahp_result.rds（給 P2 自動同步權重用）。

💻 程式碼在做什麼

# 讀取 CSV → 準則平均權重 → 反推成對比較矩陣 → AHP 求解
ahp_raw <- read.csv("ahp_weights.csv")            # 4 成員 x 6 準則
w_mean  <- colMeans(ahp_raw[, criteria])          # 準則平均權重
A       <- pairwise_from_weights(w_mean)          # a_ij = w_i / w_j
res_A   <- ahp_weights(A)                         # 特徵向量法 + CR

# Level-2：各準則下，三城市平均評分比例化後再走 AHP
X_mean <- sapply(criteria, function(cr) tapply(survey[[cr]], survey$city, mean))
score_by_criteria <- sapply(criteria, function(cr) {
  ahp_weights(pairwise_from_weights(X_mean[, cr] / sum(X_mean[, cr])))$weights
})
total_score <- as.vector(score_by_criteria %*% w_mean)   # 加權總分

提示：若你是「手填上三角的 1~9 整數」，程式裡已附 pairwise_from_upper(...)，把註解那行打開即可。

Problem 2TOPSIS 評估

📄 作業原文（English Original）

Following Problem 1, replace level-two assessment using AHP by using TOPSIS. Based on a five-point Likert scale, PIS and NIS are respectively (5,5,5,5,5,5) and (1,1,1,1,1,1). Reserve the weights of the criteria obtained in Problem 1 and calculate the weighted TOPSIS score to conduct assessment for the three cities. Discuss the differences of results between Problem 1 and Problem 2.

📋 題目說明（小學生版）

TOPSIS 就是「跟模範生比」。
想像班上有兩個虛擬同學：「完美模範生」（每科都考 5 分）和「最差同學」（每科都考 1 分）。 我們看每個城市離誰比較近：越靠近模範生、越遠離最差同學 → 就越好。
  • PIS（正理想解） = 每項都 5 分的完美城市。
  • NIS（負理想解） = 每項都 1 分的最爛城市。
  • D+ = 離完美城市多遠（越小越好）；D− = 離最爛城市多遠（越大越好）。
  • CC（貼近度） = D− ÷ (D+ + D−)，介於 0～1，越大越棒。

這題跟 P1 差在：P1 是用 AHP 比城市，P2 改用 TOPSIS 比城市，但準則權重沿用 P1 算出來的。

D+ = √( Σ wᵢ × (xᵢ − PISᵢ)² )　　D− = √( Σ wᵢ × (xᵢ − NISᵢ)² )
CC = D− / (D+ + D−)　（0～1，越大越好）

🖱️ 操作步驟

1先跑完 P1（產生 P1_ahp_result.rds），P2 會自動讀它同步權重與 P1 分數。
2確認 city_scores.csv 存在（與 P1 共用同一份評分）。要換資料時改 CSV 即可。
3執行，Console 會印出 D+、D−、CC、排名，以及 P1 vs P2 的比較表。
4作業資料夾出現 P2_TOPSIS_scores.png。

💻 程式碼在做什麼

# 權重自動同步：讀 P1 的 rds（若不存在才用內建示範值）
p1 <- readRDS("P1_ahp_result.rds"); w <- p1$weights

# 評分矩陣：直接由 city_scores.csv 算各城市平均（1~5 分）
X <- sapply(criteria, function(cr) tapply(survey[[cr]], survey$city, mean))

# 題目指定 PIS=5、NIS=1，用權重 w 算加權歐氏距離
d_plus  <- sqrt(rowSums(sweep(X, 2, PIS, "-")^2 * w_mat))   # 離完美城市
d_minus <- sqrt(rowSums(sweep(X, 2, NIS, "-")^2 * w_mat))   # 離最爛城市
cc      <- d_minus / (d_plus + d_minus)                     # 貼近度 0~1

  • CC 最大 = 最好；TopsisRank 就是名次。
  • 看 cmp 表：P1 與 P2 的排名有沒有變？重點是討論「為什麼變／為什麼不變」。
  • 小提示：TOPSIS 是「跟理想解比距離」的補償式方法；AHP 是「兩兩相對比較」。評分基準不同，排名可能就不同。
報告要寫什麼 ① CC 表與排名 ② 一句話結論（哪個城市最好）③ P1 vs P2 差異討論（這題的分數重點）④ 附 P2_TOPSIS_scores.png。

💡 管理意涵（方法差異的洞察）

  1. 兩方法結論不同，正是這題要討論的重點：AHP「高雄勝」、TOPSIS「釜山勝」。差異來自方法本質，不是資料錯。
  2. AHP 用「兩兩相對比較」→ 會放大最重準則的優勢：高雄在權重最高的「生活成本」拿滿分(5)，相對優勢被 AHP 放大，因此奪冠。
  3. TOPSIS 用「與理想解(5,5,5,5,5,5)的絕對距離」→ 偏好均衡型：釜山六項全 4 分，離完美解的距離最小（D+ 僅 1.0）；高雄雖生活成本 5 分，但旅遊只有 3 分，離散度高導致 D+ 較大，被反超。
  4. Tokyo 兩方法都是第 3：因生活成本(3)與食物(3)偏低，弱項明確，任一種方法都難以翻身 → 結論穩健。
  5. 決策啟示：若偏好「單一強項突出」（如超低生活費）→ 用 AHP；若重視「整體不偏科」→ 用 TOPSIS。方法選擇本身就是策略選擇，因此報告應說明「你們認為哪種評分方式更符合真實旅客的感受」。
  6. 穩健性建議：兩法都進前三的 Tokyo 一定墊底、高雄與釜山互有領先 → 可視為「第一梯隊由高雄、釜山競爭」。若要選唯一推薦，建議再補問卷確認權重。

Problem 3Kano 模型（手機功能）

📄 作業原文（English Original）

Apply Kano model to do evaluation for smartphones considering the features: water proof, optical zoom for cameras, wireless charging, and foldable screen. Derive the delight and the disgust based on the Kano percentages of your team members.

📋 題目說明（小學生版）

Kano 就是問「有這個功能，你開心嗎？沒有，你生氣嗎？」
對每個功能（防水、光學變焦、無線充電、摺疊螢幕）都問兩個問題：
①「如果手機有防水，你覺得怎樣？」②「如果手機沒有防水，你覺得怎樣？」
根據這兩題的答案組合，就能判斷這個功能屬於哪一類。
代號類型小學生翻譯
A魅力 Attractive有會超驚喜，沒有也不會生氣 → 加分的亮點
M必要 Must-be有是理所當然，沒有會大怒 → 沒做好就完蛋的基本盤
O一維 One-dimensional有越多越滿意，沒有就越不爽 → 越多越好的加分項
I無差異 Indifferent有沒有都無感 → 加了也沒差
R反向 Reverse有反而討厭 → 加了會扣分
Q可疑 Questionable答案自相矛盾 → 通常不列入計算

把團隊成員的答案統計成各類百分比後，算出兩個指標：

  • delight（滿意度）：有這個功能，平均多開心。
  • disgust（不滿意度）：沒有這個功能，平均多不爽（負值）。
課程範本版（本程式採用）：
delight = (A + O − I) / N　　disgust = −(M + O − R) / N
其中 N = A + M + O + R + I（不含 Q）

講義 p.16 標準版：delight = (A + O)/N　 disgust = −(O + M)/N
兩種公式結果不同！ 本程式用課程範本 Excel（多準則決策.xlsx 的 Kano 工作表）版本。 若老師要求用講義版本，請自行替換公式。交作業前確認要用哪一版。

🖱️ 操作步驟

1確認作業資料夾有 kano_survey.csv：每列 = 一位成員 × 一個功能的 A/M/O/R/I/Q 計數（程式會自動彙總成百分比）。
2要換資料時：直接改 CSV（用 Excel 開可編輯，記得存檔）。
3執行。Console 會印出每個功能的分類、delight、disgust、熵權重。

💻 程式碼在做什麼

# 從問卷計數算百分比，再算 delight / disgust（範本版公式）
cnt <- t(sapply(features, function(f)
  colSums(kano_raw[kano_raw$feature == f, kcols, drop = FALSE])))   # 4 x 6 計數
kano_pct <- cnt / rowSums(cnt)   # 每列加總 = 1

AMO     <- rowSums(kano_pct[, c("A","M","O","R","I")])
delight <- (kano_pct[,"A"] + kano_pct[,"O"] - kano_pct[,"I"]) / AMO
disgust <- -(kano_pct[,"M"] + kano_pct[,"O"] - kano_pct[,"R"]) / AMO

# 熵權重：反應差異越大的功能，權重越高
H <- -rowSums(kano_pct * log(kano_pct)) / log(5)
w_entropy <- (1 - H) / sum(1 - H)

# 輸出 rds 給 Problem 4 讀取
saveRDS(list(delight = delight, disgust = disgust, weight = w_entropy,
             features = features, category = cat_of),
        "P3_kano_result.rds")

  • 看 Category 欄：每個功能是 A / M / O / I / R 哪一類。
  • 看 Delight（越大越能增加滿意）與 Disgust（越負代表沒有時越不爽）。
  • 散布圖 P3_Kano_plot.png：橫軸 delight、縱軸 disgust，一眼看出哪些是亮點、哪些是基本盤。

Problem 4二元整數規劃 BIP（價格分群）

📄 作業原文（English Original）

Following Problem 3, apply binary integer programming to conduct price based customer segmentation. Given the base cost for a smart phone is TWD$10000, the extra costs inclusive for water proof, optical zoom for cameras, wireless charging, and foldable screen are respectively 2500, 3500, 1500, 155000. The goal is to maximize delight or minimize disgust. Derive their optimal product configuration for three segments: high (30000), medium (22000), and low (15000).

📋 題目說明（小學生版）

像在自助餐店配菜。你有 3 種價位預算（高 30000、中 22000、低 15000）。 手機本體 10000 元，每加一個功能要加錢。你要在預算以內，挑一組功能，讓客人最開心（delight 最大）。

「二元整數規劃」是什麼？每個功能只有兩種選擇：加（1）或 不加（0），「二元」就是指這個 0 / 1。 四個功能共 2⁴ = 16 種組合，程式把它們全部列出來，檢查哪一組分數最高又沒超預算。

項目金額
手機基礎成本10,000
＋ water proof 防水2,500
＋ optical zoom 光學變焦3,500
＋ wireless charging 無線充電1,500
＋ foldable screen 摺疊螢幕155,000（疑為筆誤，見下方警示）
三個價位上限high 30,000 ／ medium 22,000 ／ low 15,000
決策變數：yᵏ ∈ {0, 1}（要不要加功能 f）
目標：max Σ wᵏ × delightᵏ × yᵏ　（或 min Σ ... disgust ...）
限制：10000 + Σ costᵏ × yᵏ ≤ 價位上限
原文疑義：foldable 成本 155000 這個數字遠大於其他功能，甚至超過所有價位上限，幾乎不可能加得進去，極可能是 5000 或 15000 的筆誤。 程式中已附敏感度分析：分別用 155000 / 15000 / 5000 各跑一次給你看差別。建議先跟老師／助教確認正確數值。

🖱️ 操作步驟

1先確認 P3_kano_result.rds 存在（P3 已跑過）；沒有它，P4 會改用內建示範值。
2開啟 R-code/P4_BIP.R。成本 / 預算通常不用改。
3執行。Console 會印出「最大化 delight」與「最小化 disgust」兩種目標下，三個價位的最佳配置。
4再看敏感度分析輸出（foldable 成本不同時的差異），最後產出 P4_BIP_config.png。

💻 程式碼在做什麼

# 4 個功能 → 2^4 = 16 種 0/1 組合，全部列出
grid <- expand.grid(rep(list(c(0,1)), 4))
grid$TotalCost <- 10000 + as.vector(Y %*% cost)     # 每組總成本
grid$Delight   <- as.vector(Y %*% delight)          # 每組 delight
grid$Disgust   <- as.vector(Y %*% disgust)          # 每組 disgust

# 在預算內找最佳解（窮舉）
feas <- grid[grid$TotalCost <= budget, ]            # 只留沒超預算的
best <- feas[which.max(feas$Delight), ]             # 取 delight 最大的那組

🔍 怎麼看結果 / 報告要寫什麼

  • Configuration：該價位建議搭載哪些功能（用 + 連接）。
  • TotalCost：這組配置的總成本（必須 ≤ 價位上限）。
  • 高 / 中 / 低三個價位各有一組最佳配置 → 這就是「價格基礎的顧客分群」。
  • 報告要寫什麼：三價位配置表 + 敏感度分析結論 + 一個建議（例如：若 foldable 成本改為 X，高階機才可能搭載）。

💡 管理意涵（價格分群與產品線）

  1. 高階與中階最佳配置完全相同（都是防水+變焦+無線充，成本 17500）：因為兩者預算都足以容納這三個功能，BIP 無法把高低階區隔開。實務上高階機必須靠第四個（成本更高的）功能或材質／服務來做出差異，否則沒有升級動機。
  2. foldable 成本 155000 幾乎確定是筆誤：它比手機本體貴 15 倍、超過最高預算 5 倍以上，模型永遠不會選它 → 不是「不值得選」而是「數學上不可能」。務必先向老師／助教確認正確金額。

  5. 策略建議：高階（全功能＋摺疊）、中階（防水＋變焦＋無線充）、低階（防水＋無線充，守住基本盤）。行銷訊息分別主打「旗艦科技」、「均衡全能」、「實用安心」。
  6. 方法論提醒：BIP 是硬性預算限制下的最佳化，成本的準確性直接決定配置結果；本題也示範了「一個數字錯，整條產品線策略就變」的風險，報告中值得點出。

10. 常見錯誤排除

cannot open file 'P3_kano_result.rds' 或 P2/P4 用「內建示範值」

P2 依賴 P1、P4 依賴 P3 的輸出（*.rds）。請按順序執行， 或直接用 run_all.R 一鍵按順序跑完。用示範值時 Console 會印提示訊息。

object 'xxx' not found

你跳過了前面的段。R 是「由上往下」執行，請從第 1 段依序跑，不要跳段。

找不到輸出圖檔 / 圖跑到別的地方

每個程式開頭會自動定位到作業資料夾（Console 會印「工作目錄: ...」）， 圖檔與 rds 都輸出在那裡。從任何工作目錄執行都可以，看 Console 印出的路徑即可找到圖。

cannot open file 'ahp_weights.csv' 或「無法自動定位作業資料夾」

程式找不到資料檔：確認三個 CSV 在作業資料夾（R-code 的上一層）、檔名完全一致。 Console 若印「無法自動定位作業資料夾」，代表 CSV 被移走或改名了。

圖上的中文變成一堆方框

這是字型問題。Windows 的 R 通常可直接顯示中文；若真的變方框，改用 RStudio 開啟、並在 Console 執行 windowsFonts() 檢查字型，或把圖表文字改成英文再截圖。

結果數字跟範本 Excel 不一樣

多半是資料不同或公式版本不同。最常見是 Kano 公式（範本版含 −I / −R、講義版沒有） 與 TOPSIS 正規化（本程式用題目指定的 PIS=5 / NIS=1 錨定法）。請與老師確認要用哪一版。
