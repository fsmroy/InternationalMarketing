## 📌 課程主題摘要
本區段課程聚焦於資料探勘中**關聯規則（Association Rules）**的核心理論與經典範例推導。講師從關聯規則與監督式分類的差異切入，詳細介紹了 **Support（支援度）**、**Confidence（信賴度/信任度）** 與 **Lift（增益比/興趣度）** 三大指標。接著針對**暴力法（Brute Force Approach）**在多商品組合下的「組合爆炸」問題進行數理推導，說明為何 $d=100$ 個商品會產生高達 $5.15 \times 10^{47}$ 條規則，進而引出十大資料採礦演算法之一的 **Apriori 演算法**與其**剪枝機制（Pruning）**。最後，課程導入醫療資料集 **Pima Diabetes（印第安部落罕見糖尿病）**，示範前處理中**等寬分箱（Equal-Width Discretization）**所造成的極端分佈與自我矛盾現象，並提供自動化排序 KPI 的 R 程式碼。

## 💡 核心知識點與詳細授課內容

### 1. 關聯規則（Association Rules）與監督式分類（Classification）的根本差異
* **監督式與非監督式學習**：
  * **分類（Classification）**：屬於監督式學習，右邊（依變數/目標）必須預設完整的類別。例如產品品質分為「良品」與「不良品」。
  * **關聯規則（Association Rules）**：屬於非監督式學習，右邊（RHS）**可以單獨鎖定單一目標類別**進行觀察。
* **鐵達尼號（Titanic）實作復習**：
  * 若 RHS 單獨鎖定 `survived = yes`（獲救）：左邊（LHS）特徵組合得出最高機率為 `female`（女性）+ `class 1`（頭等艙）或 `High Fare`（高票價）。
  * 若 RHS 單獨鎖定 `survived = no`（死亡）：左邊特徵組合得出 `class 3`（三等艙）+ `low fare`（低票價）+ `male`（男性），幾乎「注定死亡」。
* **產業實務應用（中華電信機台預測維修案例）**：
  * 在進行監督式「預測維修」之前，工程團隊會先跑關聯規則。
  * 設定 RHS 為「機台故障」，觀察 LHS 有哪些硬體/環境特徵組合常同時出現（即找出 KPI）。先用非監督式關聯規則抓特徵，再進行監督式分類，屬於非常典型的 **Hybrid Project（混合式專案）**。

### 2. 關聯規則三大核心指標定義與算式

#### ① Support（支援度 / 絕對與相對機率）
* **定義**：左右兩邊（LHS 與 RHS）在所有交易紀錄中**同時被選購或同時發生的機率**。
* **算式**：
  $$\text{Support}(A \rightarrow B) = P(A \cap B) = \frac{\text{同時包含 } A \text{ 與 } B \text{ 的交易筆數}}{\text{總交易筆數 } N}$$
* **課堂範例**：5 筆交易紀錄中，包含 Milk (M)、Diaper (D) 與 Beer (B) 的筆數有 2 筆，則 Support = $2 / 5 = 40\%$。

#### ② Confidence（信賴度/信任度 / 條件機率）
* **定義**：在**給定左邊（LHS）已經發生/購買**的前提下，接著還會購買右邊（RHS）的條件機率（Conditional Probability）。
* **算式**：
  $$\text{Confidence}(A \rightarrow B) = P(B | A) = \frac{P(A \cap B)}{P(A)} = \frac{\text{同時包含 } A \text{ 與 } B \text{ 的交易筆數}}{\text{包含 } A \text{ 的交易筆數}}$$
* **課堂範例**：包含 Milk (M) 與 Diaper (D) 的交易有 3 筆（TID 1, 4, 5），在這 3 筆中接著又買 Beer (B) 的有 2 筆（TID 4, 5），則 Confidence = $2 / 3 = 66.7\%$。

### 3. 暴力法（Brute Force Approach）與組合爆炸（Combinatorial Explosion）推導

若單純設定門檻（例如 Minimum Support > 10%, Minimum Confidence > 60%），對所有可能組合逐一比對，稱為**暴力法（Brute Force）**。講師透過去高中的排列組合與二項式定理推導其不可行性：

#### ① 商品集與規則數數學推導
* 假設商店有 $d$ 個商品，每種商品有「買」或「不買」2 種選擇，總共有 $2^d$ 種商品集組合。
* 考慮將商品集劃分為 LHS（$k$ 個商品）與 RHS（$j$ 個商品），且 $k \ge 1, j \ge 1, k+j \le d$。
* 根據組合學與二項式定理（Binomial Theorem），總共可產生的可能關聯規則總數為：
  $$\text{Total Rules} = 3^d - 2^{d+1} + 1$$
* **組合數算式**（從 $d$ 中選 $k$ 個在 LHS，再從剩下 $d-k$ 中選 $j$ 個在 RHS）：
  $$C_d^k \times C_{d-k}^j = \frac{d!}{k!(d-k)!} \times \frac{(d-k)!}{j!(d-k-j)!}$$（$!$ 代表階層 Factorial，例如 $5! = 5 \times 4 \times 3 \times 2 \times 1 = 120$）。

#### ② 規則數量暴增實驗（$d=100$ 超市範例）
* 當 $d = 6$ 時：$\text{Rules} = 602$ 條（電腦瞬間可算完）。
* 當 $d = 10$ 時：$\text{Rules} = 57,002$ 條。
* 當 $d = 100$ 時（如一般超市、美聯社或全聯）：
  $$\text{Total Rules} = 3^{100} - 2^{101} + 1 \approx 5.15 \times 10^{47} \text{ 條！}$$
* **老師課堂口述 $10^{47}$ 的直觀概念**：
  * $10^6$ 為 Million（百萬），$10^9$ 為 Billion（十億）。在台灣擁有 1 億到 10 億資產（含房產股票）已名列前 2% 頂層。
  * $10^{47}$ 等於十億再乘以 5 次方倍！這是天文數字，世界上最強大的超級電腦也無法用暴力法逐一檢索。

### 4. Apriori 演算法與剪枝機制（Pruning）
為了突破暴力法的運算瓶頸，IBM 團隊提出了 **Apriori 演算法**（獲選為十大資料探勘演算法之一）。

#### ① 先驗原理（Apriori Property）
* 若 $X$ 是 $Y$ 的子集（$X \subseteq Y$），則 $X$ 的 Support 必定大於或等於 $Y$ 的 Support：
  $$\text{If } X \subseteq Y, \text{ then } \text{Support}(X) \ge \text{Support}(Y)$$
* **老師課堂生活口訣與比喻**：
  > 「你跟隔壁同學兩個人一起約吃飯簡單，還是要再加後面同學三個人一起吃飯簡單？當然是兩個人約比較簡單！人越多越難成行！」

#### ② 剪枝機制（Pruning / Delete / Remove）
* 如果發現 2 個商品組成的項目集（如 $\{A, B\}$）其 Support **未達設定門檻（Infrequent）**，代表這兩樣商品同時出現的機率太低。
* 根據先驗原理，任何包含 $\{A, B\}$ 的 3 個、4 個或 5 個商品組合（如 $\{A, B, C\}, \{A, B, D\}$），其 Support **絕對不可能通過門檻**。
* 演算法會**直接剪枝（Pruning）**，直接刪除整個樹狀分支（Branch）後續所有的搜尋與比對計算。這是一種極為聰明的 Smart Approach，讓超大型交易資料庫的關聯規則運算成為可能。

### 5. 第三個核心指標：Lift（增益比/興趣度 Interest）與經典陷阱

#### ① 「茶（Tea）與咖啡（Coffee）」經典反直覺案例
* **背景資料**（100 位顧客調查）：
  * 喜歡喝茶（Tea）者：20 人；不喜茶者：80 人。
  * 喜歡喝咖啡（Coffee）者：90 人；不喜咖啡者：10 人。
  * 茶與咖啡都喜歡者：15 人。
* **計算條件機率 Confidence**：
  $$\text{Confidence}(\text{Tea} \rightarrow \text{Coffee}) = P(\text{Coffee} | \text{Tea}) = \frac{15}{20} = 75\%$$
* **邏輯陷阱與盲點**：
  * 若單看 Confidence 高達 75%（超過 70% 門檻），決策者會誤以為「買茶的顧客也會買咖啡，因此茶可以帶動咖啡的銷售」。
  * **真相剖析**：不看茶、單獨看咖啡時，$P(\text{Coffee}) = 90 / 100 = 90\%$！也就是全體顧客本來就有 90% 的極高比例會買咖啡。
  * 當加入了「茶」之後，購買咖啡的比例反而從 **90% 降到了 75%**！茶的存在反而對咖啡產生了**干擾與抑制效果**。
* **課堂政經幽默與比喻**：
  > 「這叫作『母雞帶小雞』還是『母雞踩死小雞』？以為帶來促銷效果，結果一出現大家反而鳥獸散！就像 2022 年新竹市選情，林智堅『監哥』因論文抄襲案被台大與中華大學撤銷學位，原本要選桃園市長，結果波及整個新竹選情成為全台焦點。」

#### ② Lift（增益比）算式與判讀標準
為了修正 Confidence 的盲點，導入第三指標 **Lift**：
$$\text{Lift}(A \rightarrow B) = \frac{P(A \cap B)}{P(A) \times P(B)} = \frac{\text{Confidence}(A \rightarrow B)}{P(B)}$$
* **$	ext{Lift} > 1$**：正相關（正向促進效果，代表兩商品適合進行聯合促銷，如游泳圈與防曬油）。
* **$	ext{Lift} = 1$**：相互獨立（無任何交叉促銷效果）。
* **$	ext{Lift} < 1$**：負相關（相互排斥/抑制效果，如茶與咖啡 $\text{Lift} = 0.75 / 0.9 = 0.833 < 1$）。

### 6. 醫療資料集 Pima Diabetes（印第安糖尿病）前處理與分箱陷阱

#### ① 資料集特徵與異常值（Missing Values）處理
* **資料背景**：北美洲 Pima 印第安部落之罕見糖尿病（Rare Disease Diabetes）研究。
* **欄位與異常數據**：
  * 懷孕次數（Pregnancies）：0~17 次（老師笑談台灣少子化與自己第一份工作在私立技術學院的感受）。
  * 血糖（Glucose）、血壓（Blood Pressure）、皮脂厚度（Skin Thickness）、胰島素（Insulin）、BMI：**資料集中出現數值為 0**！
* **插補（Imputation）原則**：
  * 醫學生理資料（如血壓、皮脂為 0）屬於生理不可能現象，代表缺失值。**切勿隨意插補平均數或中位數**，否則會破壞真實醫學特徵結構；刪除 0 值後資料剩 392 筆。
  * 財經資料（如個股某日缺值）則可用前後交易日平均進行插補。

#### ② 等寬分箱（Equal-Width Discretization）導致自我矛盾的重大缺陷
課程示範將連續型變數進行「等寬切割（Equal-Width）」所產生的盲點：
* **懷孕次數（0~17 次）**：等寬中點為 8.5 次。低於 8.5 次標示為 $L$，高於標示為 $H$。由於中位數僅 3 次，導致 **682 筆樣本全都擠在 $L$ 區間**。
* **血糖（0~199）**：中點 99.5，多數樣本高於 99.5。
* **執行結果之自我矛盾**：
  * 當 RHS 鎖定「有糖尿病（`diabetes = yes`）」時，LHS 自動排序出的 Top 1 KPI 特徵包含「年齡在 20.9 ~ 51 歲」。
  * 當 RHS 鎖定「健康無糖尿病（`diabetes = no`）」時，LHS 自動排序出的 Top 1 KPI 特徵**居然同樣是「年齡在 20.9 ~ 51 歲」**！
  * **原因剖析**：因為等寬分箱導致數據分佈極度偏斜（90% 以上樣本都落在同一個區間），不論健康或生病，左邊都對應到相同的年齡區間，產生**邏輯自我矛盾**。
* **解決方案**：寫作業時應改用**中位數分箱（Median-based Discretization）**（高於中位數為 $H$，低於為 $L$），或者諮詢專業醫師取得生理臨床切分閾值。

#### ③ 自動排序 KPI 之 R 程式碼（AI 班學員提供）
利用下列 R 程式碼，可將關聯規則產生的所有 LHS 特徵按出現頻率進行自動遞減排序，快速挑選出前幾名核心 KPI：
```R
# 計算 LHS 各特徵出現頻率並進行降冪排序
lhs_features <- unlist(LIST(lhs(rules)))
feature_counts <- sort(table(lhs_features), decreasing = TRUE)
print(feature_counts[1:4]) # 印出前四大核心 KPI
```
