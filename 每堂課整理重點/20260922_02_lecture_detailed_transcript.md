## 1. 行銷數據科學架構與視覺感知心理測驗
### 1.1 行銷數據科學課程地圖
* **兩大資訊應用領域**：製造端（工業數據分析）與 行銷/電子商務端（消費數據分析）。
* **分析方法演進**：敘述統計/檢定 → STP 策略與關聯規則 (Association Rules) → 集群分析 (Cluster Analysis) → 多維尺度分析 (MDS 品牌定位) → 聯合分析 (Conjoint Analysis 偏好挖掘)。
* **工具分工**：數值與行銷結構化數據採用 **R 語言**；非結構化文字探勘與大語言模型（LLM）採用 **Python**。

### 1.2 旋轉舞者視覺感知測驗 (The Spinning Dancer Test)
* **測驗內容**：觀察剪影舞者旋轉的方向。
* **分析結果**：
  * **順時針旋轉 (Clockwise)**：占絕大多數。代表**右腦較為發達，偏向感性 (Emotional)**。感性消費者容易產生衝動購物行為（Impulsive Buying），例如對手錶、精品無抵抗力。
  * **逆時針旋轉 (Counter-Clockwise)**：代表**左腦較為發達，偏向理性 (Rational)**。
  * **順/逆時針交替出現**：代表左右腦極度平衡（Balanced），老師笑稱為「下一個賈伯斯」。
* **政治行銷與感性傳播範例**：
  * **美國與國際案例**：特朗普（川普）的著名行銷口號 "Make America Great Again" 與電視節目名言 "You're fired!"，極具感性渲染力。
  * **台灣政治行銷口號**：2018 年全台最知名口號「貨出得去，人進得來，高雄發大財」（韓國瑜），顛覆傳統選情預測；2022 年縣市長選舉、台北市選情（陳時中、蔣萬安、黃珊珊與阿扁 46% 得票天花板）、新竹市選情（鄭朝方、客家票源與竹北年輕人口結構）。
  * **老師手錶收藏與人生哲學**：談及對 Casio 電波錶、藍牙對時錶、G-Shock、Apple Watch、潛水錶及機械錶的偏好。說明人生達到特定境界後，被動收入與主動收入劃分明確，外快審查費（如國家生技園區審查費 3000 元）選擇全數捐出。

## 2. 推薦系統 (Recommendation Systems) 與關聯規則原理
### 2.1 推薦系統的兩大主軸
1. **內容導向過濾 (Content-Based Filtering)**：尋找與該使用者過往消費行為相似的其他使用者（Similar Users），根據「買過商品 A 的人也買了商品 B」來推薦產品。
2. **協同過濾法 (Collaborative Filtering)**：結合使用者的人口統計變項（Demographics：性別、年齡、所得）與過往歷史消費紀錄，進行多維度的交叉推薦。

### 2.2 關聯規則 (Association Rules) 與「啤酒與尿布」經典案例
* **購物籃分析 (Market Basket Analysis)**：掃描巨量交易資料庫，尋找經常一起被購買的商品組合。
* **經典案例：啤酒與尿布 (Beer and Diapers)**：
  * 美國超市發現週五晚上啤酒與尿布經常被同時購買。
  * **背後消費者洞察**：新手爸爸晚上在家照顧嬰兒，趁去超市買尿布時，順手帶一手啤酒作為等小孩睡著後的紓壓工具。
  * **商業價值**：如果算出「沙拉油與葵花油」或「番茄醬與美乃滋」放在一起，屬於直覺常識，毫無商業價值；唯有挖掘出「啤酒與尿布」這種看似無關但實際互補的異質組合，才能創造顯著的交叉銷售（Cross-selling）效益。

### 2.3 ⚠️ 關鍵警語：相關性不等於因果性 (Correlation ≠ Causality)
* **核心觀念**：關聯規則、卡方檢定與相關係數**只說明兩件事經常同時發生，並不代表兩者之間存在因果關係**。
* **經典反例**：某區域內速食店（麥當勞/漢堡王）開得越多，服飾店（Net）開得也越多，兩者呈高度正相關。這並不代表「開麥當勞會導致服飾店開設」，而是因為兩者背後存在共同的第三干擾因子——**區域人口密度 (Population)**！

## 3. 關聯規則三大核心指標數理推導
假設資料庫共有 **5 筆交易紀錄** (T = 5)：
1. `Milk, Bread, Diaper`
2. `Milk, Diaper, Beer, Eggs`
3. `Milk, Diaper, Beer, Coke`
4. `Milk, Bread, Diaper, Beer`
5. `Milk, Bread, Diaper, Beer`

以規則：**Milk, Diaper (LHS) → Beer (RHS)** 為例進行計算：

### 指標 1：Support（支援度 / 支持度）—— 絕對機率
* **定義**：左手邊（LHS）與右手邊（RHS）所有商品**同時出現在同一筆交易中的絕對機率**。
* **公式**：
  $$\text{Support}(X \rightarrow Y) = P(X \cap Y) = \frac{\text{Count}(X \cap Y)}{\text{Total Transactions } T}$$
* **計算**：同時包含 `Milk`, `Diaper`, `Beer` 的交易出現在第 2, 3, 4, 5 筆（其中同時包含 Bread 的為第 4, 5 筆）。若看 `Milk, Bread, Diaper, Beer` 出現 2 次，則 Support = 2 / 5 = 40%。
* **門檻設定**：由管理者自訂最小支援度門檻（Minimum Support Threshold），低於門檻者直接過濾（Pruning）。

### 指標 2：Confidence（信賴度 / 置信度）—— 條件機率
* **定義**：在**已經購買左手邊 (LHS) 商品的前提下，同時也會購買右手邊 (RHS) 商品的條件機率**。
* **公式**：
  $$\text{Confidence}(X \rightarrow Y) = P(Y \mid X) = \frac{P(X \cap Y)}{P(X)} = \frac{\text{Support}(X \cap Y)}{\text{Support}(X)}$$
* **計算**：包含 `Milk, Diaper` (LHS) 的交易共有 3 次（第 1, 4, 5 筆）；而在這 3 次中，同時也買了 `Beer` (RHS) 的有 2 次（第 4, 5 筆）。
  $$\text{Confidence} = \frac{2}{3} \approx 66.7\%$$
* **意義**：Confidence 代表 LHS 對 RHS 的驅動拉抬力道（母雞帶小雞）。

### 指標 3：Lift（增益比 / 提升度）—— 相關係數與修正指標
* **單看 Confidence 的致命缺陷（茶與咖啡案例）**：
  * 全體 100 人，喝茶 20 人，喝咖啡 90 人，兩者都喝 15 人。
  * Confidence(Tea → Coffee) = 15 / 20 = 75%（看起來很高！）。
  * 但單看咖啡的獨立購買率 P(Coffee) = 90 / 100 = 90%！
  * **發現**：原本大家買咖啡的機率高達 90%，加入了「茶」之後機率反而降到 75%！說明茶對咖啡非但沒有促銷效果，反而產生了抑制作用。
* **Lift 修正公式**：
  $$\text{Lift}(X \rightarrow Y) = \frac{P(X \cap Y)}{P(X) \times P(Y)} = \frac{\text{Confidence}(X \rightarrow Y)}{P(Y)}$$
* **判定標準**：
  * **Lift > 1**：正相關（具有顯著互補與搭售拉抬效益）。
  * **Lift < 1**：負相關（彼此排斥/抑制）。
  * **Lift = 1**：兩者獨立無關。
* *三鐵運動比喻*：跑步 10k、單車 42k、游泳 1.5k，單項分開做都可以，但三項組合在一起體力透支；園區工程師夜跑吸塵器比喻。

## 4. R 語言與 RStudio 實體操作：鐵達尼號 (Titanic) 生存分析
### 4.1 RStudio 環境與 Session 工作目錄設定
1. **套件安裝**：
   * `install.packages("arules")`：將套件下載寫入硬碟（僅需執行一次）。
   * `library(arules)`：載入 RAM 記憶體供程式呼叫（每次啟動 session 皆需執行）。
2. **設定工作目錄 (Working Directory)**：
   * 點選選單 `Session` → `Set Working Directory` → `Choose Directory`，連接至存放 CSV 數據的 `data` 資料夾。

### 4.2 資料讀取與前處理 (Data Preprocessing)
```R
# 讀取鐵達尼號 CSV 資料，header=TRUE 包含表頭，sep=","，將字串轉為類別因子
titanic_data <- read.csv("titanic.csv", header = TRUE, sep = ",", stringsAsFactors = TRUE)
```

* **⚠️ 性別編碼陷阱 (Gender Encoding Trap)**：
  * 資料集中 `Gender = 0` 代表 **Male（男性）**；`Gender = 1` 代表 **Female（女性）**。
  * 老師特別警告：千萬不要用個人刻板印象誤以為 1 一定代表男性！必須先調閱資料結構確認標籤意義。
* **缺失值清理 (na.omit)**：
  * 原始資料共 **2,208 筆**。使用 `na.omit()` 移除缺失值後剩下 **1,317 筆**。
  * 進一步過濾不合理的年齡與票價異常值（如 999 歲或 9999 歲），最終精純資料為 **1,285 筆**。

### 4.3 連續變數離散化 (Discretization / Binning)
關聯規則無法直接處理連續數值（如 1~99 歲會產生 99 個類別導致組合爆炸），必須進行分箱切割：
* **年齡 (Age) 切割**：
  * < 20 歲 → **Child / Young（年輕人）**
  * 20 ~ 50 歲 → **Adult（成年人）**
  * > 50 歲 → **Senior（老年人）** *(老師幽默自嘲自己今年 55 歲，心態上想永遠留在中年！)*
* **票價 (Fare) 切割**：
  * < 14 英鎊 → **Cheap（便宜票價）**
  * 14 ~ 33 英鎊 → **Medium（中等票價）**
  * > 33 英鎊 → **Expensive（高昂票價）**

### 4.4 關聯規則挖掘結果與「人生不平等」哲學
運用 `apriori` 演算法分別鎖定 `survived = yes` 與 `survived = no` 進行規則挖掘：

#### 🟢 獲救組規則 (`rhs = "survived=yes"`)
* 僅產出 **7 條** 高信心度規則。
* **獲救者共同特徵**：全數為 **Female（女性）**，且搭乘 **Class 1（頭等艙）** 或 **Class 2（二等艙）**，搭配高額票價。
* **結論**：頭等艙與二等艙的女性貴族享有最優先的救援資源。

#### 🔴 罹難組規則 (`rhs = "survived=no"`)
* 產出 **12 條** 高信心度規則。
* **罹難者共同特徵**：全數為 **Male（男性）**，且絕大多數搭乘 **Class 3（三等艙）**。
* **結論**：三等艙的男性幾乎全數注定罹難。
